# `dflow render` 的表格檢查

> **繁體中文** | [English](render-table-checks.en.md)

> 本頁跟著原始碼的 `main` 分支走，可能描述 changelog 還列在 `## Unreleased` 的行為。如果 `dflow render --help` 沒有 `Tables:` 那一段，就是你裝的 CLI 還不做這些檢查。`@latest` 裝的是最新**已發布**的 CLI，不保證本頁講的功能已經發布——一個已發布版本包含什麼，看它的 changelog。

Markdown 表格有兩種壞法不會出現任何錯誤訊息：表格被一個空行切斷，後面的列變成一段文字；或格子裡的 `|` 沒有跳脫，一列多出格子，多出來的字被丟掉。`dflow render` 轉每一份檔時檢查這兩種，在頁面上出問題的地方留一行提醒，命令列也逐處列出。轉換照常完成，結束碼不變。

這一頁寫清楚查什麼、查到之後怎麼修、提醒出現在哪裡，以及我們知道、但決定不查的情況。

## 查什麼

只查**最上層的表格**：不在清單項目、引言（`>`）裡的表格。判斷用的是畫頁面的同一份解析結果（Markdown 解析器 marked），所以被報的，就是頁面上真的壞掉的。

### 表格斷開

一張表後面、中間只隔空行或 HTML 註解（`<!-- … -->`）的那一段文字，第一行寫得跟那張表的列一樣，就報：

- 以 `|` 開頭，後面接一個空格或 tab；`|` 前面可以有至多三個空格；
- 以一個空格或 tab 接 `|` 結尾（最後那個 `|` 後面的空白不算）；
- 照下面「格子怎麼數」數出來的格數，跟那張表的表頭相同。

報的是斷點（空行、註解）在第幾行，以及這段開頭連續以 `|` 開頭的那幾行。這段後面（同樣只隔空行或註解）的下一段，第一行也符合時一起報，比對的仍是原來那張表；一張表被切成好幾段，每一處斷點各報一次。

- 只看第一行，是因為續列後面可能緊接著別的文字（例如一行 `Evidence:`），和續列黏成同一段；第一行像那張表的列，就是表格斷開了。
- 要「直線旁有空白」與「格數相同」，是為了不報 `|amount| 不得超過上限`、`|x| = |y|` 這類以直線開頭的算式。代價見已知限制 2 與 9。
- 中間隔著標題或任何其他區塊（清單、程式碼區塊、一般的段落）就不再往下找，所以下一個小節裡的文字不會算到這張表頭上。

### 一列多出格子，多出來的格子裡有字

表格的每一列（不含表頭、分隔列），格數多於表頭，而且多出來的格子不全是空白，就報。那些字被丟掉了，頁面上真的少了內容，這一列後面的欄也可能錯位。最常見的原因是格子裡寫了 `|` 卻沒寫成 `\|`——**反引號裡也一樣會切格子**，寫的人常以為反引號會保護它。

不報：格數少於表頭（缺的格子補成空的，畫出來跟明寫空格子一模一樣）；多出來的格子全是空白（丟掉的是空白，畫出來跟沒寫一樣）。兩種都可能藏著錯位，見已知限制 3。

### 格子怎麼數

照 marked（`dflow render` 用的那一版）切格子的規則數，但不截斷、不補齊：

- 沒跳脫的 `|` 是分隔：前面有偶數個 `\`（包括零個）的 `|` 都算。反引號、連結、HTML 裡的 `|` 也一樣是分隔。
- `\|` 不是分隔；`&#124;` 也不是。
- 切開之後，頭尾各拿掉一個空白段，所以 `| | y | z |` 是三格（第一格是空的），`a | b | c` 也是三格。

## 提醒出現在哪裡

### 命令列

有問題時，在畫圖那一段（`diagrams:`）之後、`open:` 之前多一段，每一處一行：

```text
tables: 3 problems
  problem: migration/tech-debt.md:56 — 表格在第 56 行斷開（中間有空行或註解）：……
```

檔名相對於 `--src`；行號是**原始 `.md` 檔**裡的行號，從第一行算起，frontmatter 也算在內，照這個行號打開檔案就是那一行。順序依 render 處理檔案的順序，同一份檔依行號排。每一行都附上修法。沒有問題時，這一段完全不出現。

命令列與頁面提醒只用檔名、行號、列數、格數與固定的措辭，不印任何格子或段落的內容；要看被丟掉的是哪段字，照行號打開檔案。

### 頁面

- 表格斷開：在那段沒有排進表格的文字**上方**放一行提醒，寫出斷點與那幾行的行號。
- 一列多出格子：在那張表**上方**放一則提醒，寫出是第幾列（表格裡由上往下數，不算表頭）與原始檔第幾行。一張表有好幾列多出格子，只放一則，列出所有列。
- 提醒是表格之外的獨立區塊，「卡片｜表格」兩種看法都看得到同一則；左邊有一條警示色的線，列印時照樣印出。
- 頁面上的表格與文字本身一個字不改：不把斷開的列接回去，也不把格子補回來或刪掉。頁面如實反映 Markdown——GitHub 上與 AI 讀的正本也是壞的。

### 畫圖

`analysis.md` 裡畫圖讀的表（照欄名挑出來的狀態表、轉移表、流程表）有一列多出格子而多出來的格子裡有字，或後面接著斷開，那個 `LC-nn`／`FL-nn` 就不畫圖，改印一行說明，寫出是哪張表、哪一行；命令列 `not drawn:` 那一行也照樣列出。例如：

```text
LC-01 沒有畫成圖：轉移表在原始檔第 12 行斷開，後面的列沒有讀到。
FL-01 沒有畫成圖：流程表第 2 列比表頭多出格子（原始檔第 9 行），欄位可能錯位。
```

畫圖只拿得到斷點之前的列，畫出來會少了後面的轉移或步驟；一列多出格子，那一列的值可能錯位。所以不畫半張圖。表格本身的提醒照放。小節裡畫圖不讀的表有問題，只放表格提醒，圖照畫。

## 查到之後怎麼修

### 表格斷開

- 那幾行屬於上面那張表：刪掉中間的空行；註解移到表格上方或下方。
- 那幾行是另一張表：先看那段的第一行是不是那張表的表頭。
  - 是表頭，就看下一行：那是寫錯的分隔列，就把它改對（每一格只有 `-`，可加 `:`，格數跟表頭一樣）；那是一列資料，就在表頭後面插入一行分隔列，原本的列一列都不要改掉。
  - 不是表頭：在它前面補上表頭與分隔列，兩列的格數一樣。
- 那段根本不是表格（見已知限制 9）：不用改；不想看到提醒，把它放進反引號。

### 一列多出格子

- 格子裡的 `|` 寫成 `\|`，反引號裡也一樣（在表格裡，反引號中的 `\|` 畫出來就是 `|`）。
- 如果是表頭少了一欄：在表頭與分隔列都補上那一欄。

## 不查的（已知限制）

下面這些是我們知道、但決定不查的。逐項寫出會出什麼錯、為什麼不防、誰承擔、什麼條件下會重新考慮。

1. **只查最上層的表格。** 清單項目、引言裡的表格斷開或多出格子，不會被報。
   - 為什麼不防：畫圖本來就只讀最上層的表格；巢狀表格的行號要從清單、引言的縮排換算回原始檔，容易算錯；這類表格很少見（我們量過的 755 張表裡有 18 張），也沒有一張壞掉。
   - 承擔：在清單、引言裡寫表格的作者。
   - 重看：有人回報清單或引言裡的壞表格沒被報時。
2. **續列的第一行不像那張表的列，斷開不會被報。** 例如緊湊寫法（`|a|b|`，直線旁沒有空白），或續列第一行自己就多出格子。斷開的列在頁面上仍是一段看得見的直線符號；但畫圖讀的表這樣斷開時，圖照樣只用斷點之前的列畫出來，少了後面的轉移或步驟。
   - 為什麼不防：放寬就會報到以直線開頭的算式（例如 `|x| = |y|`）。
   - 承擔：寫緊湊表格的人；讀頁面的人；讀那張圖的人（看不出圖少了幾步）。
   - 重看：有人回報時，或有人回報圖少了轉移、步驟時。
3. **格數少於表頭、多出來的格子全是空白，都不報。** 兩種畫出來都跟明寫空格子一樣（GFM 允許省略結尾的空格子）。但少的若是中間某一格，後面的值往前錯一欄；卡片看法（預設）不顯示空欄，值會出現在錯的欄名底下，看起來完全正常。例如表頭 `| Item | Amount | Status |`、列 `| sample | active |`，卡片上是「Amount: active」，看不到 Status。多出來的空格子也可能是同一種錯位的另一半。
   - 為什麼不防：機器分不出「省略了結尾」與「漏了中間」；報了就會報到合法的寫法（兩種寫法畫出來的 HTML 逐位元組相同）。
   - 承擔：讀頁面的人（尤其是卡片看法）與寫的人。
   - 重看：有人回報因此讀錯時。
4. **表格根本沒成表的不報**：分隔列寫錯、少了分隔列、表頭與分隔列格數不同，而且前面沒有表格。頁面上是一整段看得見的直線符號。
   - 為什麼不防：前面沒有表格可以比對，要判就得猜一段以直線開頭的文字是不是表格，算式與文字會被誤報。
   - 承擔：寫的人。
   - 重看：有人回報時。
5. **兩張表之間沒有空行**：下面那張的表頭與分隔列變成上面那張的兩列；兩張格數相同時不報（下面那張較寬、多出來的格子有字時，「一列多出格子」會報）。頁面上看得到一列 `---`。
   - 為什麼不防：格數相同時，接起來仍是一張合法的表，機器分不出是不是故意的。
   - 承擔：寫的人。
   - 重看：有人回報時。
6. **render 與 GitHub 的頁面不一樣時，照 render 的報。** render 轉換前拿掉 `dflow:section` 標記時，標記後面的空行也一起拿掉；斷點剛好落在那裡，render 的頁面上表格是接起來的、GitHub 上是斷的，不報。
   - 為什麼不防：檢查要報的是 render 這一頁真的壞掉的；拿掉標記是 render 轉換前本來就有的處理。
   - 承擔：在 GitHub 上讀 Markdown 的人。
   - 重看：有人回報時。
7. **只有跑 render 的人看得到。** 直接在 GitHub 或編輯器讀 Markdown 的人不會被提醒；`dflow doctor` 不做同樣的檢查。
   - 為什麼不防：落地專案靠 `dflow doctor` 確認升級有沒有生效，多一類 finding 會改變那份輸出，所以 doctor 不共用這套檢查。
   - 承擔：不跑 render 的專案。
   - 重看：有人回報沒跑 render、被壞表格誤導時——檢查寫成獨立的函式，doctor 要接上時不必重寫。
8. **格數對、內容放錯欄，看不出來。** 例如一列漏了一格又多了一格。
   - 為什麼不防：要判斷內容放錯欄，就得讀懂內容，機器判不準。
   - 承擔：寫的人與審查的人。
   - 重看：有人回報時。
9. **極少數不是表格的文字會被報成斷開**：緊接在表後（只隔空行或註解）、第一行以 `|` 加空白開頭、以空白加 `|` 結尾、格數又剛好跟那張表相同，例如把 |a| + |b| 寫成 `| a | + | b |` 接在三欄的表後。提醒照報；那段本來就不是表格，不用改；不想看到提醒，把它放進反引號。
   - 為什麼不防：要排除它，就得在「第一行寫得跟那張表的列一樣」之外，再猜內容像不像算式；這種寫法極少見，提醒也附了處理方式。
   - 承擔：寫這種算式的人。
   - 重看：有人回報時。
